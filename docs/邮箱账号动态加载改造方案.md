# 邮箱账号动态加载改造方案（替代手工改配置）

## 1. 背景与目标

当前邮件监控系统通过 `config.properties` 固定配置邮箱账号（如 `IMAP_USERS`、`IMAP_AUTH_CODES`、`SOURCE_MAILBOXES`、`TARGET_MAILBOXES`）。
这会导致每次新增联系专员或客户时都要手工改配置，不利于工程化、自动化和长期维护。

本方案目标是：

- 新增/修改联系专员或客户后，无需再手工改配置文件。
- 邮件监控系统自动从 CRM 数据库加载需要监控的邮箱账号。
- 邮箱账号变更可在运行时生效（轮询刷新或事件触发刷新）。
- 授权码等敏感信息避免明文散落在配置文件中。

---

## 2. 现状问题

当前配置文件中包含大量“动态业务数据”，例如：

- 监控源邮箱：`SOURCE_MAILBOXES`
- 监控目标邮箱：`TARGET_MAILBOXES`
- IMAP 登录邮箱：`IMAP_USERS`
- IMAP 授权码：`IMAP_AUTH_CODES`

这些值本质上是“业务对象（人/客户）的数据”，不是“系统静态配置”。

建议保留在配置文件中的仅包括：

- IMAP 主机、端口、协议
- 轮询周期
- 下载目录
- CRM 接口地址与鉴权参数
- 数据库连接参数

---

## 3. 推荐总体方案

将邮箱监控从“静态配置驱动”改为“数据库驱动”：

1. 邮件监控服务启动时，从 CRM 数据库查询可用邮箱账号列表。
2. 按固定周期（如 60 秒）刷新账号列表并做增量更新。
3. 新增联系专员/客户后，只要数据写入数据库，监控服务自动感知。
4. 配置文件只保留系统级静态参数，不再写具体邮箱名单。

---

## 4. 数据来源映射（结合你当前库）

根据你提供的信息，建议先按以下规则实现：

### 4.1 联系专员邮箱

- 表：`sys_user`
- 字段：
  - `email`（邮箱）
  - `email_auth_code`（授权码）

### 4.2 客户邮箱

- 主表：`customer`
- 扩展字段表：`customer_field`
- 规则：
  - `customer_field.resource_id = customer.id`
  - `customer.owner = sys_user.id`（`owner` 字段就是客户负责人，指向 `sys_user.id`）
  - 客户邮箱固定字段 ID：`field_id = 177676248585700000`
  - `customer_field.field_value` 为客户邮箱值

> 说明：如果后续字段 ID 可能变化，建议将“客户邮箱字段 ID”做成系统参数表配置，而不是硬编码。

## 5. SQL 示例

以下 SQL 仅作实现参考，请按你们实际字段类型/索引调整。

### 5.1 查询可监控的联系专员邮箱

```sql
SELECT
    su.id              AS owner_id,
    su.email           AS mailbox,
    su.email_auth_code AS auth_code
FROM sys_user su
WHERE su.email IS NOT NULL
  AND su.email <> ''
  AND su.email_auth_code IS NOT NULL
  AND su.email_auth_code <> '';
```

### 5.2 查询客户邮箱（来自 customer_field）

```sql
SELECT
    c.id               AS customer_id,
    c.owner            AS owner_id,
    cf.field_value     AS customer_mailbox
FROM customer c
JOIN customer_field cf
  ON cf.resource_id = c.id
 AND cf.field_id = '177676248585700000'
WHERE cf.field_value IS NOT NULL
  AND cf.field_value <> '';
```

### 5.3 生成最终监控账号视图（建议）

可在代码中组装，也可做数据库视图：

- 源邮箱（source）：联系专员邮箱
- 目标邮箱（target）：客户邮箱
- 关联关系：`customer.owner = sys_user.id`
- 业务含义：同一个 `owner_id` 下面，联系专员邮箱作为发送方，负责人名下客户邮箱作为目标方

## 6. Java 侧改造要点

## 6.1 新增“动态账号提供器”

新增一个组件，例如：`MailboxAccountProvider`

职责：

- 定时查询数据库
- 产出结构化账号列表（owner、邮箱、授权码、客户目标邮箱集合）
- 与当前内存账号做 diff（新增、删除、变更）
- 通知 IMAP 监听器做增删改

建议数据结构：

```java
public class MailboxAccount {
    private String ownerId;
    private String sourceMailbox;
    private String authCode;
    private Set<String> targetMailboxes;
    private boolean enabled;
}
```

## 6.2 监听器增量更新

避免每次刷新都全量重连，建议：

- 新增账号：创建新监听任务
- 删除账号：优雅停止并释放连接
- 授权码变化：重建该账号连接
- 目标邮箱变化：仅更新过滤规则

## 6.3 刷新策略

- 默认每 60 秒刷新一次
- 启动时立即刷新一次
- 刷新失败不影响现有监听，保留上一次成功快照

## 6.4 缺失授权码处理策略（必须实现）

当新增联系专员仅填写 `email`、未填写 `email_auth_code` 时，按以下规则处理：

1. 不纳入监控：
   - 该账号不创建 IMAP 连接，不参与邮件监听。
2. 可观测告警：
   - 记录一条结构化告警日志，内容至少包含 `ownerId`、`email`、`reason=missing_auth_code`。
   - 建议汇总到监控指标：`mailbox_skipped_missing_auth_code_count`。
3. 前端/管理侧提示：
   - 在“邮箱监控状态”中标记为“待授权”，提示“已填写邮箱，未填写授权码，暂未启用监控”。
4. 自动生效：
   - 一旦后续补齐授权码，下一次刷新周期自动纳入监控，无需重启服务。

实现口径（建议统一）：

- “可监控账号”定义为：`email` 非空且 `email_auth_code` 非空。
- 缺失授权码属于“数据不完整”，不是“系统异常”；不应导致服务整体失败。

## 7. 配置文件迁移建议

从 `mail monitoring/config.properties` 中逐步移除这些动态项：

- `SOURCE_MAILBOXES`
- `TARGET_MAILBOXES`
- `IMAP_USERS`
- `IMAP_AUTH_CODES`

保留：

- `USE_IMAP`
- `IMAP_HOST`
- `IMAP_PORT`
- `IMAP_FOLDER`
- `POLL_SECONDS`
- `ATTACHMENT_*`
- `DB_*`
- `CRM_*`

可新增静态配置：

```properties
MAILBOX_DYNAMIC_LOAD_ENABLED=true
MAILBOX_REFRESH_SECONDS=60
CUSTOMER_EMAIL_FIELD_ID=177676248585700000
```

## 8. 安全与稳定性建议

### 8.1 安全

- 禁止在日志打印完整授权码（仅显示前后 2 位）
- 优先将 `email_auth_code` 改为加密存储（AES 或 KMS）
- 数据库账号最小权限化

### 8.2 稳定性

- 对单账号失败做隔离，不影响其他账号监听
- 对失效授权码做自动告警并标记
- 做邮箱地址合法性校验，过滤脏数据
- 对 `email` 有值但授权码为空的账号执行“跳过 + 告警 + 待授权标记”，避免重复认证失败重试

---

## 9. 分阶段实施（建议）

### 阶段 1：最小可用

- 接入动态加载联系专员账号
- 先不做复杂加密，先完成自动化替代手工配置
- 保留旧配置开关，支持快速回退

### 阶段 2：完整业务关联

- 加入客户邮箱映射（owner -> customer target）
- 完成监听过滤规则动态更新

### 阶段 3：增强治理

- 授权码加密存储
- 监控告警和可观测性（成功率、失败率、连接数）
- 管理后台“监控账号启停”能力

---

## 10. 上线前检查清单

- [ ] 新增联系专员后，60 秒内自动开始监控其邮箱
- [ ] 新增联系专员仅填邮箱未填授权码时，系统会跳过该账号并标记“待授权”
- [ ] 新增客户并填写邮箱后，过滤规则自动生效
- [ ] 删除或禁用账号后，监听连接自动释放
- [ ] 授权码错误时有明确告警与重试策略
- [ ] 配置文件已不再包含具体邮箱账号与授权码明文

---

## 11. 结论

你的目标是合理的，但“自动写配置文件”不是最佳工程实践。

推荐使用“数据库动态加载 + 定时刷新 + 增量更新监听器”的方案。
这样可以从根本上解决“每次新增联系专员或客户都要手工改配置”的问题，同时提升可维护性、安全性和可扩展性。
