# 智能体查询结果完整性与分页

参考 SQLBot，列表回答默认返回最多 1000 条，同时使用相同权限、筛选条件和时间范围统计总数；总数不超过 1000 条时一次返回全部记录。
例如数据库匹配 234 个分组时，表格和图表均包含全部 234 组；超过 1000 条时提示总数和剩余数量，并可继续查看下一页。
点击“继续查看”或在当前会话输入“继续查看／下一页”，沿用服务端保存的查询条件获取下一页。
聊天页提供“限制 1000 行数据”开关，Web 和移动端默认开启，并保存在当前浏览器；请求通过 `limitRows` 传递该设置，不需要新增数据库迁移。
开启时，每个结果页最多返回 1000 条；要求“全部”也遵循此上限。关闭后，新查询不添加默认的外层行数限制，返回全部符合条件的结果。
明确要求前 N 条、前 N 名或每组前 N 名时，始终保留模型 SQL 中的业务限制。开启开关时单次传输仍最多 1000 条；关闭时不限制明确的 N。
查询超时、只读权限和外部数据源的结果体积保护仍生效，关闭行数限制并不保证任意大小的结果都能返回。

排名查询和普通分页分别处理：销售额前十先在全部符合条件的合同数据上按客户汇总、按金额排序，各币种分别取十名。默认展示限制只作用于最外层结果，不截断统计输入。榜单不超过 1000 条时一次显示，榜单自身超过 1000 条才分页；不会把未入选的其余客户作为榜单的“剩余结果”。相同金额按分组字段稳定排序，取恰好 N 名（不足 N 名时返回实际数量）。

销售额口径固定为外部 `contract_info.amount`，日期为 `release_date`；不同币种分别统计和排名。显式要求每月排名时按月份、币种分别排名。日期范围先识别完整起止日期，再处理单月与相对时间；不带年份的 `1~6月` 使用当前年份，跨年须写明年份。开始日期包含，结束日期整天包含。

对“这批结果按金额从高到低排序”等追问，沿用服务端保存的查询条件，按当前权限重新执行完整数据库汇总排序，并遵循当前行数开关。即使只保存了前页或分析上下文已裁剪，也不对那部分数据冒充全量排名。不能确定查询对象、指标或时间时先澄清。

排名 SQL 使用 MySQL 8 的 `ROW_NUMBER()`，不依赖模型在聊天上下文中计算名次。测试覆盖同一客户多笔金额汇总、各币种前十、完整半年和跨年范围、1234 组分为 1000／234、恢复历史筛选条件及权限变化。

适用范围：通用白名单实体查询，包括客户、CRM 合同、加工单、跟进、邮件、企微和外部合同／时间轴；
负责人客户名单、可见客户名单、最近客户名单统一使用这条路径。旧外部订单列表也统计总数并支持分页。
分组查询统计的是符合条件的分组总数，不将分组数量称为客户或订单数量。

总数统计失败时保留可用明细，明确显示总数和剩余数量尚未核实。
旧组合／信号查询尚不能证明全量范围时，统一提示结果范围未核实，不用明细条数冒充总数。
模型分析另受上下文长度限制，必须区分 `totalRows`、`returnedRows`、`includedRows`、`complete`。
`truncated=false` 只说明未裁剪当前批次，不能证明查询已覆盖全部记录。

全部已返回记录直接展示，无需点击展开；“继续查看”会发起新的查询。
表格限制高度，可上下左右滚动，滚动时保留表头。
图表使用全部已返回且经过权限控制、脱敏的数据，不再截取前 50 组或前 6 个币种/单位分组。分类较多时通过底部缩放条查看后面的分类。
图表数据独立于模型分析上下文的 100/200 行与字符预算；完整图表随回答保存，历史回答可重新查看。
完整查询标注“已绘制本次查询的全部结果”，仍有未获取记录时明确标注非完整查询结果。重复分类无法明确分组时不强行生成图表。
更新前已保存的回答不会自动补查当时未返回的数据，需要重新提问。
结果区域分别展示符合条件总数、本次获取条数、表格当前展示条数和剩余未获取条数。
分页条件保存在服务端会话快照中，客户端仅提交原回答的消息 ID。
每次翻页校验用户、组织、会话和数据权限，并重新构建当前权限过滤条件。
列表使用稳定排序；数据库数据在翻页之间发生新增、删除或排序字段变化时，建议重新查询。

验证覆盖：234 组完整表格和图表、结果总数不超过 1000 条时一次返回全部、超过 1000 条按页返回、关闭限制返回 1234 行、聚合输入不受展示限制、明确前 N 条、同条件计数、分组计数、总数失败、全部请求、上下文裁剪、
消息归属校验、权限变化和旧外部订单分页。真实数据库总量以部署后的查询为准。
