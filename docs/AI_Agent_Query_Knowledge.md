# 问数知识库

## 页面和用途

侧边栏原“公司知识库”已改名为“问数知识库”。进入后，顶部有“术语配置”和“SQL 示例库”两个独立页面。

- 术语配置：名称、描述、同义词、启用状态、生效数据源。术语可用于所有数据源，或指定多个数据源。
- SQL 示例库：问题描述、只读 SQL、启用状态、生效数据源。每条示例必须绑定一个数据源。
- Web 支持新增、编辑、详情、搜索、状态筛选、数据源筛选、批量删除、Excel 导入导出、匹配测试。手机端提供分类切换、搜索、详情和增删改、启用开关。

例如，配置术语“品种”，同义词为“产品型号”，描述为“采购品种使用 contract_info.product_name；采购数量使用 total_quantity，并按 unit 分组，不使用加工订单原料字段”。然后在实际存有这些表的数据源下，保存问题“各品种采购总量”及经过核对的 SELECT 示例。

## 问数流程

1. 校验当前用户、组织及数据源访问权限。
2. 使用 SQLBot 的提示词提取查询关键词，历史上下文只提供用户提问；提取失败时使用原问题。同义词扩展只用于选表，术语检索使用原始提取关键词。
3. 仅检索当前组织、已启用、适用于当前数据源的知识。逗号分隔的关键词逐个匹配术语名称/同义词；SQL 示例使用未扩展的关键词文本匹配。匹配不区分英文大小写。
4. 术语名称和每个同义词分别建立向量，不把说明加入向量。每个关键词分别进行语义匹配，按名称/同义词向量取相似度大于阈值的前若干项，再取回对应术语的完整说明。向量匹配与字面匹配取并集，去重后限制上下文大小。
5. 在 SQL 生成提示词中提供当前表结构、术语和 SQL 示例。模型需按当前问题调整时间、条件、方言，不能直接执行示例，不能引用当前 schema 中不存在的表字段。
6. 实际生成的 SQL 仍经过原有只读校验、表白名单、CRM 数据权限及脱敏控制，再执行查询。
7. 对真实查询结果做分析时，只注入术语定义，不注入 SQL 示例。

这是运行时参考资料检索和提示词增强，不是训练或微调模型。知识不保证模型完全遵守，应通过“匹配测试”、实际 SQL 查看和样例问题校验效果。

## 数据隔离与权限

配置页面及导入导出、匹配测试需要 AGENT:UPDATE，删除需要 AGENT:DELETE。普通问数沿用原有 AGENT:READ。

全数据源或 CRM 术语在当前组织共享。指定多个数据源的知识，只有能访问全部绑定数据源的配置人员才能管理；问数时只要求用户可访问当前数据源且该知识适用于它。自定义数据源沿用已有用户所有权校验。跨组织不能读写。

避免在术语或示例中存放密码、客户隐私、敏感字面值。匹配内容会发送给当前问数大模型；开启向量时，术语名称、每个同义词，以及 SQL 示例的问题会发送给配置的向量服务，术语说明不用于建立向量。

## 导入导出

先在对应页面点击“导入”并下载模板，保留表头。支持单工作表 .xlsx/.xls 或 UTF-8 CSV，文件不超过 5MB，一次最多 200 条，不接受公式。

- 术语同义词列用 JSON 数组，例如 `["产品型号","产品品种"]`。
- 术语数据源列用 `ALL` 表示所有，或用 `;` 分隔数据源 ID/唯一名称。
- 示例数据源只能填一个 ID/唯一名称，不能填 ALL。
- 内置数据源用 `CRM` 或 `内置 CRM`。
- 启用列填 true/false；留空默认启用。
- 导入新增条目，不覆盖同名条目；作用域重叠的名称或同义词冲突时拒绝导入。
- 任何一行失败，整批回滚。导出可用于备份；重复导回同一个库会触发重复校验。

每个组织最多 2000 条知识。保存、停用和删除使用版本号，避免旧页面覆盖别人刚保存的内容。

## 后端语义检索配置

语义检索只读取后端 `crm.ai-agent.query-knowledge` 配置，不再提供前端设置窗口和配置修改接口。以前通过前端保存到数据库的组织配置不再覆盖文件配置；旧配置表保留，不删除历史数据。未启用时保留关键词匹配，启用后与向量匹配取并集。

本地开发使用项目根目录 `cordys-crm.properties`；安装部署使用后端实际加载的 `/opt/cordys/conf/cordys-crm.properties`，模板在 `installer/conf/cordys-crm.properties`。文件已有配置示例，也支持 `QUERY_KNOWLEDGE_EMBEDDING_ENABLED/URL/MODEL/API_KEY` 环境变量覆盖示例中的默认值。更改配置后重启后端。

向量服务须兼容 OpenAI embeddings 协议，可以是本地服务或外部服务，与问数聊天模型分别配置。

### 本地模型示例

先安装并启动 Ollama，然后运行 `ollama pull bge-m3`。在后端实际加载的配置文件中设置：

```properties
crm.ai-agent.query-knowledge.embedding-enabled=true
crm.ai-agent.query-knowledge.embedding-url=http://127.0.0.1:11434/v1/embeddings
crm.ai-agent.query-knowledge.embedding-model=bge-m3
crm.ai-agent.query-knowledge.embedding-api-key=
crm.ai-agent.query-knowledge.similarity=0.4
crm.ai-agent.query-knowledge.top-count=5
crm.ai-agent.query-knowledge.max-context-chars=24000
crm.ai-agent.query-knowledge.index-batch-size=10
crm.ai-agent.query-knowledge.index-initial-delay-ms=5000
crm.ai-agent.query-knowledge.index-poll-ms=30000
```

Ollama 示例不需要 API Key。若 CRM 在 Docker 容器中、Ollama 在 Windows 宿主机上，把地址改为 `http://host.docker.internal:11434/v1/embeddings`，并确认服务允许容器访问。URL 应为完整 embeddings 接口地址，不是 chat/completions 地址。

已有外部向量服务时，把地址、模型、密钥替换为服务商实际提供的配置即可。不要把密钥提交进版本库。

### 自动索引和验证

保存术语时为名称和每个同义词分别生成向量，问数时为每个原始关键词生成匹配向量。独立后台任务在启动约 5 秒后开始检查已有的已启用条目，每轮最多 10 条，每轮结束后间隔 30 秒继续。旧的“名称＋同义词＋说明”术语向量会标记为待重建，后台自动改建为独立词向量；SQL 示例索引格式不变。旧条目、生成失败的条目和服务地址/模型变更后的条目也会自动补建或更新索引；失败条目不阻塞后面的条目，下轮扫描会重试。并发编辑的旧版本不能覆盖新版本索引。

1. 重新构建、部署前后端，并重启使用新配置的后端。
2. 等待后台补建，刷新术语列表，确认“语义索引”为“已就绪”。条目较多或模型首次加载时需要更久。
3. 在新聊天中输入“埃及有哪些客户”，查看“处理过程”中的提取关键词及术语匹配记录；“匹配测试”可以输入同样的逗号分隔关键词，例如“客户,埃及”，复核术语检索结果。
4. 后端日志 `Query knowledge semantic indexing: success=..., failed=..., stale=...` 记录补建结果；持续失败时检查地址、模型是否已下载、API Key 和服务连通性。

“已就绪”表示条目向量与当前后端模型配置一致；具体问题是否召回还取决于问题向量、相似度阈值和适用数据源。检索到术语不保证模型完全采用规则，仍需核查 SQL。

向量服务失败时仍可关键词匹配。向量请求有超时，开启后大批量导入会更慢，建议分批导入。后台索引会使用配置的向量服务，外部服务的请求可能计费。

## 旧逻辑和部署

原上传文档、切片召回、从文档提取业务规则的流程已退出问数链路，旧上传接口及自动解析调度不再注册。聊天附件仅用于当前聊天，不能自动写入问数知识库。

旧表和文件保留作历史备份，不自动转换为术语或示例，也不再影响新回答；没有执行清库或删除旧文件。需要把有用定义人工整理成术语，把验证过的查询整理成示例。

重新构建并重启后端，新表由迁移 `V1.6.0_54__ai_agent_query_knowledge.sql` 创建。构建并部署新前端。仅刷新页面不会让正在运行的旧后端获得新接口。

开发前端地址沿用 http://127.0.0.1:5173/。浏览器界面测试使用模拟 API，后端测试使用本机内存 H2 和模拟大模型，没有连接业务数据库或外部模型服务。
