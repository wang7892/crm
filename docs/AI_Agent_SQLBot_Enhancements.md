# 问数与 SQLBot 的流程对齐

本次以本地 SQLBot-main 的问数流程和原生模板为参照，修改 CordysCRM-1.6.0 的问数路径。SQLBot-main 仅作为参考，未修改。CRM 的组织权限、行权限、字段脱敏和独立数据连接继续由宿主执行层处理。

## 查询流程

1. 使用 SQLBot 原生关键词提取提示词，关键词提取只带近期用户问题。
2. 从业务术语扩展同义词，用关键词和表结构向量检索相关表。融合权重为向量 0.4、关键词 0.6，保留明确提及的表，补齐最多 10 个检索位置，并扩展关联路径。缺失向量批量生成并缓存；元数据或模型配置改变时使用新的缓存键。
3. 检索当前数据源适用的术语和 SQL 示例。读取相关表的真实样例：最多 3 行、前 10 个可查询字段，文本截断到 100 字符。内置表通过现有权限编译器读取；样例不执行总数统计。
4. 使用 SQLBot 原生 SQL 模板和对应数据库方言生成 SQL，直接传入最近 3 轮用户问题与 SQL 回复。追问不先经另一个模型改写，不执行预设问题处理器。
5. 由宿主执行层验证只读 SQL、注入权限范围和脱敏，执行查询。失败保存模型生成的 SQL 与经过处理的错误反馈，供下一问或“重新生成”使用。
6. 使用 SQLBot 原生图表模板生成维度、指标和分类映射，图表数值取自实际查询行。图表失败不丢弃查询结果。最多生成 4 个推荐追问。

原生模板位于 backend/crm/src/main/resources/aiagent/sqlbot-templates.json，来自 SQLBot-main/backend/templates/template.yaml 和 sql_examples 目录。FILE 数据源使用 H2 方言兼容配置。

向量检索使用现有 crm.ai-agent.query-knowledge.embedding-* 配置。未配置嵌入模型时使用关键词检索；模型与嵌入服务必须由运行环境提供。

问数模型选择提供 GPT-6.1 Sol（primary，模型标识 gpt-6.1-sol）和 DeepSeek-Flash。千问已从聊天模型选项及本地配置中移除；DeepSeek 配置位于 providers[0]。Docker 启动脚本与地址覆盖同步使用这一索引。

GPT 主供应商可通过 `crm.ai-agent.llm.api-type=responses` 使用 `/v1/responses`。本地 GPT 配置已启用；默认值及 DeepSeek 仍为 `chat-completions`。Responses 在主要模型任务请求 `reasoning: {effort: "medium", summary: "auto"}`，接收 `response.reasoning_summary_text.delta` 及完整响应的 `reasoning.summary`，将供应商提供的推理摘要显示在现有“思考过程”中并保存到历史记录。流式正文、JSON 输出、图片、近期对话、取消请求和失败重试沿用原有调用约定；Token 统计映射 Responses 的 input_tokens/output_tokens/total_tokens。

GPT 可公开的推理摘要不等于完整内部思考，是否返回还取决于模型和转发接口。当前转发接口实测在数字推理题返回了摘要，但部分 SQL 生成请求没有返回摘要；没有摘要时保持空状态，不将处理日志或额外生成的说明伪装成模型思考。单纯启用流式输出或出现 reasoning_tokens 统计，不能保证有摘要文本。

## 结果与操作

- resultTable 分别保存列键、标签、类型和真实结果行。新查询不依靠换行或中文冒号拆分表格，不把大数值自动猜成时间戳。旧历史记录保留原有文本表格显示兼容。
- chartConfig 保存模型生成的展示配置；charts 保存从真实数据生成的图形。支持表格、柱状图 column、条形图 bar、折线图 line、饼图 pie，以及多指标或分类序列。
- 分析与预测由用户显式触发，使用所引用的已保存查询结果，不自动补查。预测返回的未来周期行存入 predictionTable，趋势图同时显示历史数据与预测数据，预测线段使用虚线。
- 重新生成使用所引用记录的原始问题和失败反馈，历史上下文截至该记录之前。不会自动触发 SQL 修正循环。
- 推荐追问由模型根据表结构、当前问题与近期问题生成。点击追问沿用该结果的数据源。
- Excel 导出所引用的已保存结果；单元格文本按字面值写入，不执行公式。超出 Excel 数字精度的长数字以文本保存。
- 分析、预测、重新生成、继续查看和导出都校验会话所有者、组织、当前数据权限及数据源版本。
- modelCalls 保存每次模型调用的阶段、供应商、实际模型、耗时、成功状态和供应商返回的 Token 数；供应商未返回 Token 时留空。原有 llmProvider/llmModel 保留为最后一次成功调用的兼容信息。
- 回答底部显示“消耗 Tokens”“耗时”和“执行详情”。durationMs 按主要问答开始至完成的实际时间记录，包含检索、模型与 SQL 执行；totalTokens 汇总该问答的模型用量。与 SQLBot 一致，独立的推荐追问不计入这两项统计。模型没有返回用量时显示“—”。
- 执行详情抽屉的问数列表按 SQLBot 归并为七项：提取关键词、匹配术语、匹配 SQL 示例、匹配数据表 (Schema)、生成 SQL、执行 SQL、生成图表结构。相关步骤的耗时与展开内容合并展示，失败状态保留；未执行的步骤不补造。电脑与手机端使用同一组件。统计和步骤随回答快照保存；旧记录也按这七项归并，不补造总耗时，不需要数据库迁移。
- “提取关键词”展开后显示模型提取的原始关键词；没有有效提取结果时，显示实际使用的原问题检索输入。旧快照中放在选表结果里的关键词也归到此处，选表使用的同义词扩展内容仍保留在“匹配数据表”中。
- 回答上方的“思考过程”按 SQLBot 展示模型实际返回的连续文本，移除原来的编号处理阶段组件。读取 OpenAI 兼容接口的 reasoning_content，也支持 content 开头的 `<think>...</think>` 思考标签及分片标签。SQL 和图表生成实时发送思考片段，但不把生成的 JSON 当作回答输出；分析与预测同样保留思考文本。关键词和推荐追问的思考不混入回答。失败请求的片段清除后再展示重试结果。
- reasoningContent 随回答快照保存，Web 与手机端共用可折叠的“思考中 / 思考过程”展示。每条智能体回答保留按钮；模型未返回思考文本或旧记录没有该字段时，展开显示“本次回答没有可展示的思考内容”，不生成替代思考文字。用户问题不显示该按钮；执行步骤继续用于底部执行详情，无需数据库迁移。

请求新增 action（QUERY / ANALYSIS / PREDICT / REGENERATE）与 referenceMessageId。Excel 接口为 POST /ai-agent/result/export，请求携带 sessionId、referenceMessageId、question 和原数据源 datasourceId。

## 清理范围

已移除问数主入口里的固定问法分支、旧查询计划路由、追问改写、自动补查、排序补查、置信度拦截、自动修正 SQL 和按字段猜测图表的逻辑，并替换对应测试。通用 SQL 解析、权限编译、数据库连接、知识管理、附件和语音模块保留。

不增加 SQLBot 中没有的业务口径校验、多查询补查、自动纠错或评测平台。流程与功能对齐不意味着不同模型、数据结构和术语配置会产生完全相同的 SQL 或回答；真实效果需要在相同模型和数据条件下对照。
