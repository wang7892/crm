# 真实企业微信会话存档接入步骤

## 1. 企业微信后台准备

1. 确认已开通「会话内容存档」，并且存档范围包含需要监控的联系专员。
2. 记录企业 ID（`WECOM_CORP_ID`）和会话存档 Secret（`WECOM_CORP_SECRET`）。
3. 在会话存档配置里生成或上传 RSA 公钥，并把对应私钥保存到服务器本地文件，供 `WECOM_PRIVATE_KEY_PATH` 使用。
4. 下载企业微信会话存档 Finance SDK，把 Java JAR 放进运行 classpath，把 native 动态库所在目录加入 `PATH`。

## 2. CRM 主数据准备

1. CRM 的 `sys_user.wecom_id` 必须等于企业微信成员 `userid`。监控程序会自动读取这个字段作为被监控联系专员列表。
2. CRM 客户表 `customer.wecom_external_id` 必须维护客户企微 `external_userid`。
3. 如客户企微 ID 仍使用自定义字段，建议在 `cordys-crm.properties` 里配置：

```properties
crm.wecom.customer-external-field-internal-key=你的客户企微字段internalKey
# 或者更直接：
# crm.wecom.customer-external-field-id=字段ID
```

## 3. 监测服务配置

不要把 Secret 写进仓库。开发机可用环境变量；生产建议用服务管理器或密钥管理系统注入。

```powershell
$env:WECOM_CORP_SECRET="替换为后台重新生成后的Secret"
```

`config.properties` 至少改这些值：

```properties
ORGANIZATION_ID=100001
WECOM_CORP_ID=ww真实企业ID
WECOM_PRIVATE_KEY_PATH=E:/secure/wecom-msgaudit-private.pem
CRM_INGESTION_DB_ENABLED=true
```

联系专员 userid 不再写入 `config.properties`，统一从 CRM 库 `sys_user.wecom_id` 读取；客户匹配使用 `customer.wecom_external_id`。

## 4. 验证链路

1. 启动 CRM 后端，确认 `crm.wecom.auto-create-follow=true`（默认开启）。
   默认 `crm.wecom.auto-follow-current-day=true`，CRM 会每分钟消费待同步消息，并自动写入匹配客户的跟进记录。
2. 启动 `wecom monitoring`。
3. 用被监控专员和一个已维护 `external_userid` 的客户发一条消息。
4. 检查 CRM 库：

```sql
SELECT * FROM wecom_ingestion_session_day ORDER BY update_time DESC LIMIT 5;
SELECT * FROM wecom_ingestion_message ORDER BY create_time DESC LIMIT 5;
```

5. 如果 `wecom_ingestion_session_day.status` 变成 `SUCCESS` 且有 `follow_record_id`，说明已自动生成跟进记录。

常见失败：

- `CUSTOMER_NOT_MATCHED`：CRM 客户没有维护对应 `external_userid`，或字段配置不正确。
- `STAFF_NOT_MATCHED`：CRM 用户 `sys_user.wecom_id` 没有维护成企业微信成员 `userid`。
- `Finance SDK unavailable`：classpath 缺少 SDK JAR，或 `PATH` 缺少 native 动态库目录。
- `WeCom RSA private key unavailable`：`WECOM_PRIVATE_KEY_PATH` 路径错误，或私钥格式不对。
